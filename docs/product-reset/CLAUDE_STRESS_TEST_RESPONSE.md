# Response to the July 12 Claude stress test

**Status:** reviewed and independently checked; decision record  
**Source:** Claude Code Fable 5 Max, 40-agent workflow, completed after the interactive session hit
its output limit. The raw local task artifact is not product authority.

## Overall judgment

The review was valuable. It accurately distinguished the well-tested pair foundation from the
mostly contractual group direction, found real validation drift, and surfaced Google storage/session
rules that required immediate correction. Its best contribution was forcing sequencing discipline:
stop adding speculative layers until the data boundary, validation ladder, and chat bridge are real.

The review does not reverse the owner's explicit decision that recurring 2–6 person groups are the
product center. A pair remains the smallest group and the cheapest Phase A test of the shared core.
Only Phase B group evidence can approve group production.

## Accepted with a different decision

### Do not freeze or erase the group direction

Claude's focus lens recommended demoting groups and running only the pair pilot. That is too strong:
the owner explicitly rejected pairs as the emotional/product center, and the group prototype exposed
real requirements a pair-only product hides. The disciplined sequence is:

1. remediate Google compliance;
2. run Phase A on the already-built pair core;
3. build only the minimum group foundation if Phase A supports accumulated taste;
4. run Phase B on real recurring groups;
5. allow Phase B—not prose—to approve production groups.

### Overture is chosen, not yet a solved exit

Claude's data lens correctly says the durable catalog must be owned/open. Overture Places is now the
chosen single development spine after a current source/access/license comparison, but it is not an
immediate availability claim: ingestion, release-level attribution review, refresh, area resolution,
identity drift, and conflation are material engineering. Rows pin release/schema/license-ledger
provenance, only general `open` status is eligible, and Google can never correct owned fields. See
[`OPEN_CATALOG_DECISION.md`](OPEN_CATALOG_DECISION.md).

### Keep the discovery contract, defer its trust layer

Name-only candidates are not viable, so final-three enrichment remains necessary. Anonymous taste
neighbors, persisted similarity edges, and learned ranking remain disabled until real density and
privacy evidence exist. Structured group evidence and live bounded enrichment come first.

## Not adopted

- Groups do not have to “emerge from pair density.” Real families and recurring friend circles may
  begin as groups once Phase B proves the flow.
- The approved visual baseline is not deleted. Visual exploration is bounded and already useful;
  it simply cannot substitute for validation or backend progress.
- Chat-history ingestion is not promoted to activation. It introduces consent, third-party-message,
  sensitive-text, and model-cost issues that are larger than a shareable outbound receipt.
- No price or subscription promise is made before product utility. The existing no-paid-placement
  law remains; revenue design follows evidence.
- Google/Overture cost estimates are planning inputs, not assurances. SKU telemetry and hard quotas
  must verify them before external use.

## Corrected execution order

1. Finish the Google data/compliance boundary and retire unsafe catalog paths.
2. Make manual browser evidence reproducible.
3. Run Phase A pair validation without claiming it validates groups.
4. If Phase A supports the shared core, implement groups, attendee-scoped plans, server projections,
   server retrieval, attributed vetoes, derived-data rights, and the chat receipt.
5. Run Phase B and let its cold-plan, multiplayer, organizer-concentration, plan-#2, and trust results
   decide whether group-native this.is proceeds.
